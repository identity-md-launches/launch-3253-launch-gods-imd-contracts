# GODS OF IMD launch adaptation

The target is Ethereum, chain 1: OracleShrine first, then GodsOfIMDInhabitants. Constructors and their argument order are unchanged. There is no token or pool deployment, ETH funding, initializer, proxy, factory setup call or broadcast. The manifest keeps `$owner` and the backward `$contract:OracleShrine` reference; the actual director is the supplied game server address. Genesis supply remains 1,000, including the 100 reserved souls, with the unchanged 640 / 250 / 100 / 10 Mark deck.

The task specifically permits changes required by reproduced audit findings. All source changes below use that exception. Every pre-existing ABI entry (including constructor, errors, events and return tuples) remains present unchanged; additions are ten shrine ABI entries and one inhabitants event. The `tokenOfSoul` lookup semantics and stale-reveal completion semantics require the integration updates in README.md despite preserving their ABI shapes.

## Imported audit disposition

1. **`dd2b89d5ff3a` — reproduced and fixed with minimum-policy enforcement.** The original supplied test failed with “next call did not revert as expected”: a 3-of-3 attestation could settle the rewards pin. The new default floors reject it and also reject a 20-seat answer even if 20 agree. Tests show a qualifying answer can activate and pay the reserved rewards. The contract still passes the director's JSON body through; the floors are an owner policy, not a parser or a per-request snapshot of the paid panel. The owner must align them with the required security level before asks, and can change the policy for pending pins.
2. **`0a96368412f2` — reproduced and fixed for the known-hash fallback.** The original supplied proof obtained Divine (4) or Mortal (1) for the same soul by selecting its late reveal block. Both branches now remain Unrevealed and schedule unknown future entropy. Separate tests prove a later retry completes, updates a single deck counter, and cannot reveal twice. This is not a VRF: shared-deck reveal ordering, block producers, transaction rollback and repeated expiry can still influence outcomes. Prompt independent reveals remain an operational assumption. No claim of manipulation-proof randomness is made.
3. **`77392183468b` — reproduced and fixed by minter-scoped uniqueness.** A local original-code test had a funded copier forge a pending raw hash, then observed the designer's `SoulAlreadyForged` revert. Regression tests now let the designer forge successfully after the copy via public, allowlist, alternative-token and both reserve entry points, while duplicate hashes from the same original minter still revert. Content itself is public and can be copied; the chosen audit remedy prevents identity squatting, not plagiarism or proof-of-authorship disputes. The server must use the minter-scoped identity.
4. **`32ff888ca852` — reproduced under the stated retirement scenario and fixed.** A mock Intake selling only `oracle.request@oracle-2` refused the old `askRewards` while generic `ask` could select the new action. The owner can now migrate the rewards action without redeployment. Tests exercise the original failure, rollback of reservations/pins, the owner update, payment of the new request and successful old/new outstanding answers. No claim is made that the live action has already retired.
5. **`e128f904206e` — reproduced capacity limitation, documented recovery.** With cold shrine storage, three-element lists exhaust the 200,000-gas callback allowance; one/two elements and boolean rewards fit. Fuzz tests cover 1–8 nonzero elements for both list types and confirm `record` stores the exact answer after an unsuccessful callback. Storage and the callback remain unchanged. Operators must relay larger lists; a failed callback is not automatically retried. The protocol's exact one-element signature also fits.
6. **`c451ebefaf069` — confirmed trust assumptions, not a defect.** The NFT owner can lower prices to zero, alter payees/splits/royalties/forge-token settings and wallet caps, and redirect shrine/burn addresses. The shrine owner can withdraw free IMD and other tokens, change signer/intake/director/price/quorum/reward cap and now panel/action policy. Reserved IMD remains protected. The director chooses questions and reward roots/totals; the oracle judges them. The steward controls memorial and metadata status, not transfers. The director is the explicitly supplied server wallet; stewardship and other initial owner roles belong to `$owner`. These intended powers were retained.
7. **`c27e01796f64` — coverage statement, not a defect.** The original 50-test suite passed locally. Rechecked the deployed shapes, constructor execution, runtime restrictions, exact conformance vector, unchanged deck and payment tests, reward accounting paths and actual address wiring. No application source was inaccessible. The pinned owner's inherited floor helper was not included among the supplied files; the submitted factory rehearsal independently asserts ownership and configured payees. Live Ethereum JSON-RPC reads on 2026-11-13 at block **26,402,880** confirmed code at Intake v2, IMD, SHIFT and the burn sink; the signer and director had no code. IMD reported `Identity.md`, 18 decimals; SHIFT reported `NIGHTSHIFT`, 18 decimals; `priceOf(bytes32("oracle.request@oracle-1"), IMD)` returned **500000000000000000**. These reads confirm configuration, not external-token source safety. Token source audits, transfer-fee and pause behavior were not independently verified.

No supplied defect was dismissed as non-reproducible. The action-retirement finding is a reproduced hypothetical future state, not an observed live outage. The two informational operational/trust findings were documented and tested rather than used to redesign the application.

## Verification

- Original baseline: 50/50 tests passed with the supplied seed; both supplied exploit proofs failed as reported. Additional local original-code probes confirmed soul copying, retired-action failure and large-list callback exhaustion.
- Final `forge build` succeeded with lint warnings, and `FOUNDRY_FUZZ_SEED=0xafac6a10467d0f616e14402e8a4b5e608e9406ab5a5ab0a50531ae9b9684d54b forge test` passed **83/83 tests in 13 suites**, including five fuzz tests with 256 cases each. Both use the unchanged project configuration. All tests are self-contained and require no network or credentials.
- ABI artifact comparison against the original build found no removed or changed ABI entries. Both constructors remain nonpayable, with five and four address words respectively. Manifest schema, counts, order and notes were checked against those artifacts.
- Runtime byte sizes: **OracleShrine 16,232**, **GodsOfIMDInhabitants 17,960**; both below EIP-170's 24,576 bytes and both pass the protected reachable-opcode scan. Constructor init code also passes the 49,152-byte limit in the local factory rehearsal.
- No Slither, Mythril, live deployment, transaction signing/broadcast or explorer verification was run. This work does not replace the independent final audit. Original reproduction scaffolding under `test/scratch` is not a delivered dependency; the submitted regression tests are outside it.
